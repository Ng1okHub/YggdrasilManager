# 開源前的待決事項

[English](open-source-readiness.en.md) | **繁體中文** | [简体中文](open-source-readiness.zh-CN.md)

檢查日期：2026-11-27。Release 建置、Manager 版本來源、本機簽名工具、GitHub 驗證與發佈流程、README 及更新紀錄已就緒。公開前仍需完成以下決策與檢查。

## 首次公開發佈前

1. **選擇專案授權**。根目錄目前沒有 `LICENSE`，GitHub 也未辨識出專案授權。公開儲存庫本身不會授予他人重用權。請先選擇自己擁有之程式碼的授權，並核對核心 ABI 標頭、原生相依套件、JVM 相依套件及前端資源的相容性，再加入授權檔案。目前尚未代為選定授權。
2. **補齊第三方署名與聲明**。內附的 `libunwindstack-ndk/LICENSE` 包含 Apache 與 Unicode 聲明，個別原生檔案也保留上游著作權標頭。請稽核原生、Gradle 與 npm 相依套件的授權，保留必要聲明，並決定如何隨 APK 分發，例如「關於／授權」頁面搭配聲明資源檔。
3. **決定瀏覽器控制台的存取方式**。兩個伺服器目前都監聽 `0.0.0.0`（HWBP 為 `8765`、Syscall 為 `8766`），且無須身分驗證便可接受設定指令。請記錄可信任網路的使用前提；廣泛分發前，可考慮預設只監聽 localhost 並透過 ADB 轉送，或加入身分驗證與來源驗證。這屬於另一項產品決策。
4. **將發佈金鑰備份到工作區外**。請保留 `.signing/yggdrasilmanager-release.p12` 與 `keystore.properties` 的加密副本，並確認能重現公開憑證。四項 GitHub Actions Secrets 已設定，但無法取代可復原的備份。
5. **進行 release 真機冒煙測試**。安裝 release APK，檢查 Root 綁定、模組偵測、四項工具、兩種瀏覽器控制台與內附自測程式。宣稱支援 Android 7 時需涵蓋 API 24／25；若有條件，也應包含 16 KB 記憶體分頁裝置。JVM 測試、lint、簽名驗證與 ZIP 對齊檢查無法證明這些執行期行為。

## 儲存庫維護

- 推送審閱完成的變更，確認首次 GitHub Actions 執行結果。為預設分支（檢查時為 `master`）設定 CI 必過與審閱規則，並保護版本標籤。目前 GitHub 方案下的私有儲存庫無法查閱 rulesets（API 回傳 HTTP 403）。
- 定義貢獻方式與漏洞回報管道。目前缺少 `CONTRIBUTING.md`、`SECURITY.md`、issue 範本與 PR 範本。Issue 指引應包含支援的模組版本與最小診斷資訊。
- 變更可見性前，檢查完整 Git 歷史中的憑證與私人資料。目前忽略規則可保護新的簽名檔，但不會移除既有 commit 中的內容。本次變更尚未執行完整歷史的機密掃描。
- 在更新紀錄中記錄測試過的裝置／模組組合與首次發佈日期。前端 lockfile 更新後，相依套件 audit 已無告警；Android lint 尚有相依套件更新與未使用資源等警告。

檢查時儲存庫為私有。請完成上述公開發佈檢查後，再變更可見性。
